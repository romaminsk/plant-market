# ADR-0016: Дата и окно доставки

- **Статус:** Accepted
- **Дата:** 2026-11-10
- **Решающие:** AI-лид (автономный режим владельца)
- **Связанные документы:** ADR-0013, `docs/status.md`

## Контекст

Checkout собирал зону и адрес, но не дату доставки. Покупатель не мог выбрать удобный день и
интервал, а оператор не видел ожиданий по доставке.

## Решение

- В заказе появились `delivery_date date` и `delivery_window varchar(20)`.
- Окно — enum `MORNING`, `DAY`, `EVENING`; ёмкость окна пока не ограничивается.
- `checkout` принимает `deliveryDate`/`deliveryWindow`; дата проверяется по
  `today + zone.minDays … today + zone.maxDays` в UTC.
- Если клиент не передал оба поля, используются `today + minDays` и `DAY` — старые API-клиенты
  продолжают работать.
- Storefront показывает дату и окно, ограничивает дату диапазоном выбранной зоны и отправляет
  оба поля через BFF.

## Последствия

- Нет лимита на количество заказов в окне; для реального слота нужна таблица `delivery_slots`
  с capacity и конкурентным резервированием.
- Граница даты — UTC; для мультирегиональности понадобится зона клиента.
- Существующие заказы и тесты без даты получают детерминированное значение по умолчанию.

## Проверка

- `OrderFlowIntegrationTest`: дата/окно сохраняются, дата вне диапазона даёт 400.
- `CheckoutFlowE2ETest` и гостевые сценарии выбирают дату/окно и оплачивают заказ.
