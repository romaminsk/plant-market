## ЧАСТЬ A. КОНСТИТУЦИЯ

Эти правила действуют в каждой сессии. Изменять — только через ADR и явное подтверждение человека.

### A1. Продукт

**Plant Market** — интернет-магазин редких комнатных растений в Беларуси.

**Чем отличается от всех остальных:** продаём не «фото похожего растения», а **конкретный экземпляр** (WYSIWYG) — с фото листьев, корней, дефектов, уникальным кодом, происхождением и гарантией. Плюс честная зимняя доставка и поддержка после покупки.

**Кто платит и за что:**
1. Розница — растения, кашпо, грунты, уход. Основной доход.
2. B2B — озеленение офисов, корпоративные подарки, обслуживание.
3. SaaS (позже) — подписка для продавцов растений на учёт и заказы.

**Метрики успеха MVP (3 месяца после запуска):**

| Метрика | Цель |
|---|---:|
| Конверсия каталог → заказ | ≥ 2,0% |
| Средний чек | ≥ 120 BYN |
| Повторные покупки за 90 дней | ≥ 20% |
| Смертность и повреждения при доставке | ≤ 3% |
| Доля WYSIWYG-позиций в заказах | ≥ 40% |
| Возвраты и споры | ≤ 2% |

**Явно НЕ делаем в MVP:** маркетплейс чужих продавцов · аукционы · live-шопинг · мобильное приложение · продажи за пределы РБ · своя курьерская служба · Kubernetes.

### A2. Персоны

| Кто | Боль | Как решаем |

| **Коллекционер** (25–45) | «Пришлют не то, что на фото» | WYSIWYG: фото конкретного экземпляра, код, корни, происхождение |
| **Новичок** (22–35) | «У меня всё умирает» | Подбор по свету и опыту, care-инструкции, напоминания, гарантия 48 ч |
| **Интерьерный покупатель** | Нужен крупномер целым | Фильтр по размеру, доставка с подъёмом, кашпо в комплекте |
| **Компания** | Нужен счёт, договор, повторное обслуживание | B2B-кабинет, инвойсы, озеленение под ключ |
| **Продавец растений** (фаза SaaS) | Excel, потеря заказов, нет учёта черенков | Учёт партий, черенков, смертности; заказы; мультиканал |
| **Оператор магазина** | Ручная сборка, путаница в остатках | Админка: каталог, остатки, заказы, претензии |

### A4. Доменная модель (главное в проекте)

| Термин | Что это |
|---|---|
| **Product** | Позиция каталога: «Monstera deliciosa Albo Variegata». Описание, категория, care-гид. Не продаётся напрямую. |
| **ProductVariant** | Продаваемая конфигурация: размер, горшок, форма. Имеет SKU и цену. |
| **IndividualPlant** | **Конкретный живой экземпляр** с уникальным кодом и фото. Штучный товар: 1 штука = 1 экземпляр. |
| **StockBatch** | Партия поставки: количество, себестоимость, поставщик, дата, срок карантина. |
| **Reservation** | Временная блокировка остатка под корзину или заказ. Имеет время жизни. |
| **PropagationUnit** | Черенок или детка от маточника: родитель, дата отделения, стадия, прогноз готовности. |
| **MortalityRecord** | Списанное растение: причина, себестоимость, партия, дата. |
| **Order** | Заказ: позиции, суммы, статусы оплаты и доставки. |
| **Claim** | Претензия: тип, фото, решение. |

**Инварианты (нарушение = баг, а не фича):**
1. `IndividualPlant` нельзя продать дважды. Из `SOLD` обратно в `AVAILABLE` — только через отмену заказа.
2. Сумма зарезервированного никогда не превышает доступный остаток.
3. `Order.total = subtotal + shipping + tax − discounts`. Пересчёт **только на сервере**, никогда во фронтенде.
4. Растение в статусе `QUARANTINE` недоступно к продаже.
5. Зимняя доставка не предлагается, если температура в регионе назначения ниже порога и термоупаковка не выбрана.
6. Деньги хранятся как целые в минимальных единицах (`amount_minor` + `currency`). Никаких float/double.

### A5. State machines

**IndividualPlant:** `ACQUIRED → QUARANTINE → AVAILABLE → RESERVED → SOLD → DELIVERED`. Ветки: `→ MORTALITY`, `→ RETURNED → AVAILABLE`.

**Reservation:** `ACTIVE → CONFIRMED | RELEASED | EXPIRED`. TTL корзины — 15 минут.

**Order:** `DRAFT → PENDING_PAYMENT → PAID → FULFILLING → SHIPPED → DELIVERED → COMPLETED`. Ветки: `CANCELLED` (только до `SHIPPED`), `REFUNDED`, `FAILED`.

**Payment:** `CREATED → PENDING → CONFIRMED → CAPTURED`. Ветки: `FAILED`, `REFUNDED`, `PARTIALLY_REFUNDED`.

**Claim:** `OPENED → UNDER_REVIEW → RESOLVED(REPLACEMENT | REFUND | REJECTED)`.

**Shipment:** `PLANNED → HANDED_TO_CARRIER → IN_TRANSIT → DELIVERED | RETURNED_TO_SENDER | LOST`.

Каждый переход — явная команда сервиса, запись в `*_status_history` и событие.

### A10. Конвенции

**Java.** Пакет `by.plantmarket.<service>`. Слои: `config / controller / service / data.entity / data.repository / model.dto / model.mapper / messaging / client / ex / validation`. Только constructor injection. DTO — records. Маппинг — MapStruct. В публичных API вместо `null` — `Optional`.

**REST.** База `/api/v1`. Ресурсы — множественное число, kebab-case. Пагинация: `?page=0&size=20&sort=field,asc`, ответ `{items, page, size, totalElements, totalPages}`. Ошибки — **RFC 7807** `application/problem+json`: `type, title, status, detail, instance, traceId, errors[]`. Все `POST`, создающие деньги или заказы, требуют заголовок `Idempotency-Key`. Заголовок `X-Request-Id` прокидывается сквозь все сервисы и попадает в логи.

**База данных.** Таблицы и колонки — snake_case. PK — `id UUID`. Обязательные колонки: `tenant_id`, `created_at`, `updated_at`, `version` (optimistic lock). Soft delete (`deleted_at`) только там, где есть юридическая причина: orders, payments. Миграции Flyway: `V<yyyyMMddHHmm>__<описание>.sql`, только вперёд, никакого `DROP` без ADR.

**События.** Топик `pm.<domain>.<action>.v<N>`, ключ партиции — `aggregateId`. Конверт:
```json
{
  "eventId": "uuid",
  "eventType": "order.created",
  "eventVersion": 1,
  "occurredAt": "2026-11-01T10:00:00Z",
  "tenantId": "uuid",
  "aggregateType": "Order",
  "aggregateId": "uuid",
  "traceId": "hex",
  "payload": {}
}
```
Публикация только через outbox-таблицу. Потребитель идемпотентен по `eventId`. Retry 3× с экспоненциальной задержкой → DLQ `pm.<domain>.<action>.v<N>.dlq`.

**Frontend.** TypeScript `strict: true`, никаких `any`. Server Components по умолчанию, Client — только где нужно. Формы — React Hook Form + Zod. Запросы — TanStack Query. Apollo Client 4 — только в client components; на сервере `fetch` + типы из codegen.

### A11. Безопасность и право (РБ)

**Техника:**
- OAuth2 Authorization Code + PKCE. Access token 10 мин, refresh с ротацией; повторное использование refresh = отзыв всей цепочки.
- Cookie: префикс `__Host-`, флаги `Secure`, `HttpOnly`, `SameSite=Lax`. Для cookie-флоу — CSRF double-submit.
- Пароли — Argon2id.
- Роли: `CUSTOMER`, `OPERATOR`, `MANAGER`, `ADMIN`, `SYSTEM`. Фильтр по `tenant_id` обязателен в каждом repository + интеграционный тест на отсутствие утечки между тенантами.
- Rate limit на gateway: 60 req/мин/IP для публичных, 10/мин для login и register.
- Заголовки: HSTS, CSP, X-Content-Type-Options, Referrer-Policy, Permissions-Policy.
- Секреты: dev — `.env` (в `.gitignore`) + `.env.example`; prod — Vault или SOPS. Нигде в коде, логах и текстах ошибок.
- Логи без PII, токенов, номеров карт, полных адресов.
- Платежи — только hosted payment page / redirect (уровень SAQ-A). PAN не хранить и не логировать.

**Юридический чек-лист РБ — проверить с юристом ДО Phase 2. Не реализовывать вслепую.**

### A13. Тестирование

| Уровень | Инструменты | Норма |
|---|---|---|
| Unit | JUnit, Mockito | ≥ 70% строк; ≥ 80% для денег, остатков, статусов |
| Slice | Spring Test, MockMvc/WebTestClient, Testcontainers | все контроллеры и repository |
| Integration | Spring Boot Test + Testcontainers (Postgres, Kafka, Redis) | каждый сервис стартует и проходит happy path |
| Contract | WireMock, OpenAPI/GraphQL schema diff, protobuf compatibility | все внешние интеграции |
| E2E | Playwright Java | все 6 сценариев A3 + smoke |
| Accessibility | axe-core | 0 critical на ключевых страницах |
| Visual | Playwright screenshots | карточка, каталог, checkout |
| Performance | k6 или Gatling | каталог p95 < 300 мс, checkout p95 < 800 мс, 50 RPS без ошибок |
| Security | OWASP ZAP baseline, Trivy, dependency-check | 0 high/critical |

**Правила:**
- Тестовые данные — билдеры и фабрики, не хардкод. Тест сам создаёт и сам убирает данные.
- Запрещён `Thread.sleep`. Только явные ожидания Playwright/Awaitility.
- Детерминированность: время через инжектируемый `Clock`, случайность через инжектируемый `Random`.
- E2E не зависят от порядка и идут параллельно (изоляция через уникальные email и SKU).
- Платежи и доставка в E2E — только через WireMock.
- Flaky: максимум 1 повторный прогон в CI. Тест, упавший повторно без изменения кода, в тот же день уходит в карантин + issue.

**Definition of Done для любой задачи:**
тест написан до или вместе с кодом → `./gradlew build` зелёный → покрытие не упало → статический анализ без новых предупреждений → токены и i18n соблюдены → a11y проверен для UI → документация и ADR обновлены → миграция обратима или это задокументировано → в diff нет секретов → коммит в Conventional Commits → PR ≤ 400 строк.

### B6. Оркестрация агентов — экономия токенов без потери качества

Проект делает не один агент, а **ведущий + субагенты**. Цель: минимум токенов на единицу проверенного кода.

#### B6.1 Роли

| Роль | Кто | Забирает из контекста | Возвращает |
|---|---|---|---|
| **Ведущий** | основная сессия | держит карту проекта, контракты, статус | решения и интеграцию |
| **Разведка** | `recon` / `explore` | чтение и поиск чужого кода | бриф ≤ 40 строк с `file:line` |
| **Исследователь** | `general` | веб-поиск, документация, version spike | факты со ссылками |
| **Рабочий** | `worker` | реализация в явном наборе файлов | изменённые пути + вывод команд |
| **Проверяющий** | `verifier` | сверка готового со спецификацией | расхождения, без рассуждений |

#### B6.2 Семь правил экономии

1. **Ведущий держит карту, а не территорию.** Он не читает целиком файлы, которые не правит. Разведку делегирует, получает сжатый бриф.
2. **Контракты пишутся один раз.** `contracts/` (OpenAPI, `.proto`, GraphQL SDL, схемы событий) создаёт ведущий. Рабочие реализуют **по файлам контрактов**, а не по пересказу в промте. Это главный источник экономии: интерфейс не нужно объяснять каждому агенту заново.
3. **Бриф самодостаточен, но минимален.** Рабочему даётся: задача · точные пути файлов · какие контракты читать · что он производит для соседей · Definition of Done · лимит объёма ответа. История переписки и архитектура целиком — не передаются.
4. **Один агент — один непересекающийся набор файлов.** Никогда два агента в одном модуле. Параллельность только по границе сервиса/модуля.
5. **Ответ сжат.** Рабочий возвращает: изменённые пути · фактический вывод команд · число прошедших и упавших тестов · отклонения. Без дампов файлов и без повествования. Лимит — 40 строк.
6. **Прочитанное субагентом не перечитывается.** Ведущий доверяет брифу, пока его не опровергнет упавшая команда.
7. **Проверяет машина, а не агент.** Тесты, линтер, Trivy, Lighthouse, axe-core — в CI. Перечитывать код глазами вместо запуска тестов — прямая трата токенов.

#### B6.3 Экономия на boilerplate

- `platform-common` содержит error handler (RFC 7807), фильтр `X-Request-Id`, DTO пагинации, базовые тест-утилиты. Сервисы подключают модуль, а не копируют код.
- Клиентский код генерируется из контрактов: OpenAPI generator, protobuf-плагин, GraphQL codegen. Сгенерированное не пишется вручную и не перечитывается агентом.
- Шаблоны в репозитории: каркас сервиса, ADR, PR, runbook. Рабочий копирует шаблон вместо изобретения.
- Точечные запуски: `./gradlew :services:catalog-service:test`, а не `./gradlew build` на каждой итерации. Полная сборка — только на гейте фазы.
- Чтение файлов — через `grep`/`glob` и с offset/limit. Не `cat` больших файлов.

#### B6.4 Распределение по фазам

**Phase 0** (последовательно там, где есть зависимость, параллельно где нет):

| Шаг | Кто | Задача | Параллельно |

#### B6.5 Ограничения

- Максимум **4** субагента одновременно.
- Вложенное делегирование запрещено: субагент не создаёт своих субагентов.
- Одна повторная попытка при переходном сбое, дальше ведущий делает сам.
- Не делегировать задачу, которую решает один `grep` или одно чтение файла.
- Не делегировать, чтобы «занять всех». Субагент, вернувший «ничего не найдено», стоил дороже, чем поиск ведущего.
- Если объяснение задачи дольше самой задачи — ведущий делает её сам.

#### B6.6 Как не потерять качество

Экономия токенов не отменяет проверки. Обязательны:

1. **TDD** для доменной логики: деньги, остатки, статусы, резервы.
2. **Ведущий сам запускает команды** из отчёта рабочего и сверяет вывод. Отчёт без вывода команд не принимается.
3. **`verifier` со свежим контекстом** на каждом гейте фазы: получает спецификацию и артефакты, но не рассуждения ведущего.
4. **DoD из A13** — для каждой задачи, не только для фазы.
5. **Архитектурные правила проверяются тестом**, а не договорённостью: ArchUnit-тест запрещает сервису импортировать пакет другого сервиса и обращаться к чужой БД.
6. **Инварианты A4 покрыты тестами**: двойная продажа экземпляра, отрицательный остаток, пересчёт суммы на клиенте.
